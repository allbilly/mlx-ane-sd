# M1 macOS → Asahi full-ANE handoff

The full-stack reference is in
[artifacts/m1-full-ane](../artifacts/m1-full-ane/README.md). It is approximately
**5.54 MB**, alongside the earlier 45 MB microkernel reference. Model weights,
compiler weight BLOBs, complete weight-bearing HWX files and bulk input/output
dumps are excluded. Public checkpoints stay external; compact templates and
recipes reconstruct every HWX byte locally. The superseded 1.106 GB packaging
was removed from the unpublished commit, with the original captures retained
locally.

## Measured scope

The original [native macOS receipt](m1_m4_recipe.json) remains unchanged:
72.0037 tok/s SD versus 45.1869 tok/s MLX BF16 Metal, or **1.59346×**.
The same LUT6 target's padded B=8 ANE AR control measured 53.3553 tok/s,
giving **1.34951×** SD/control. All eight SD trials match that compressed AR
target. The compressed target differs from BF16. This is the public compatible
Qwen3-0.6B DFlash pair; neither a 3× mean nor the original M4 4B experiment was
reproduced.

Both target chunks contain 14 layers and capture hidden states 1/13 and 25.
Draft context projection and the three-layer body use per-tensor LUT6; target
and vocabulary head use grouped-channel LUT6 with group size 16. Block B=8,
capacity C=256, seven proposals, greedy acceptance and accepted-prefix-only
cache commits match the measured experiment.

## Compact reconstruction

The packing approach follows the external-checkpoint pattern in the local
`~/ane/gpt2` reference, inspected read-only. For each projection, scalar
boundaries preserve the measured quantizer assignments. Six-bit indices and
FP16 palette means are recomputed from the public BF16 tensor; sparse rounding
corrections preserve the original palette exactly. Recipes retain the compiler's
engine/channel ordering, including fused SiLU gaps and the eight-channel final
vocabulary tile. Norm vectors also come from safetensors.

All learned coefficient regions are zeroed in the compressed HWX templates.
Audits reject unexplained coefficient residue; only identified fixed activation
tables remain. Original commands, symbols, sections and BAR bindings remain
intact. Full HWX hashes check the assembled containers, not just the matrices.
All **243 matrices and 114 norm vectors** reconstruct successfully across five
programs; see [the reconstruction receipt](../artifacts/m1-full-ane/reconstruction.json).

Real prompt/cache inputs are regenerated by the portable host loop. The kit
retains their hashes, shapes and generation traces, rather than input/output
binary dumps. A NumPy 1.26 versus 2.4 sine-rounding difference was found during
this check. A **40,341-byte fixed RoPE math table** removes that version
dependence without retaining per-call model inputs.

Using the exact measured CoreML ANE models, regenerated inputs and all **588
outputs across 72 calls** match the original hashes; all four 100-token SD
traces also match. See [current compact-kit validation](m1_compact_reference_validation.json).
This is correctness validation, not a replacement throughput measurement or
execution of offline HWX. The earlier
[AR/SD host validation](m1_full_ane_host_validation.json) records the original
portable-loop comparison.

## Entry points

- [derive_m1_lut6_templates.py](../scripts/derive_m1_lut6_templates.py) reads
  local full captures, derives recipes, removes learned banks and checks exact
  reconstruction. Positional constants use the measured NumPy 2.4.6 environment.
- [m1_lut6_weights.py](../scripts/m1_lut6_weights.py) loads pinned external BF16
  safetensors and builds verified runtime HWX files in an ignored cache.
- [package_m1_full_stack.py](../scripts/package_m1_full_stack.py) builds and
  verifies the small kit; it rejects bulk weight/input/full-HWX files.
- [m1_hwx_decode.py](../scripts/m1_hwx_decode.py) regenerates command/register
  metadata from reconstructed HWX. [m1_hwx_tool.m](../scripts/m1_hwx_tool.m) and
  [capture_m1_full_stack.py](../scripts/capture_m1_full_stack.py) preserve the
  macOS export and standalone MIL evaluation workflow.
- [m1_ane_replay.py](../scripts/m1_ane_replay.py) plans buffers and submits
  programs through the Linux ANE DRM ABI. Interior/aliased BARs and unbound
  external surfaces are rejected.
- [m1_full_ane_host.py](../scripts/m1_full_ane_host.py) runs the portable cache,
  argmax and acceptance loop with the fixed positional table.
- [run_m1_full_ane_replay.py](../scripts/run_m1_full_ane_replay.py) provides
  offline plan/reconstruction, strict Linux golden verification and the paired
  four-prompt benchmark.
- [verify_m1_full_ane_macos.py](../scripts/verify_m1_full_ane_macos.py) checks the
  regenerated inputs/outputs against existing verified macOS artifacts.

The ABI was checked against local
`allbilly/ane@fd0831e0ef76812c1c6b0138d4532da1dd33a8b9` without modifying it.
Compiler/loading interfaces were cross-checked with
[coreml_to_ane_hwx](https://github.com/freedomtan/coreml_to_ane_hwx) and
[ane_pmu_profiler](https://github.com/freedomtan/ane_pmu_profiler).

## Asahi validation remains necessary

Follow the bundle README for pinned `hf download` commands and Linux runs.
Its offline commands select a macOS or Linux NumPy environment explicitly;
the `asahi_python.sh` wrapper is used for Linux hardware verification and
benchmarking. The Linux benchmark uses the same stock greedy
`mlx_lm.stream_generate` baseline and `generation_tps` metric as the macOS
receipt. All three configurations warm each of the four prompts before any
measured row. Receipts keep those calls separate and state each configuration's
timing convention.
No macOS capture archive or compiler environment is needed. Reconstructed
runtime binaries occupy approximately 502 MB locally; these contain model
coefficients and are deliberately excluded from Git.

All five plans resolve external tensors, scratch and coefficients. The driver
supplies BAR1 at the aligned constant tail; the planner checks its delimiter
against the entire task chain. The separate queue bootstrap uses network ID
`0x40`; retained command descriptors are unchanged. Linux allocates runtime
IOVAs. No live macOS MMIO or firmware readback is claimed.

Direct precompiled macOS loading failed at stage 4 / underlying `0x1`, while
standalone MIL execution succeeded. The Linux driver's full descriptor-chain
support, numerical identity and throughput still need hardware testing. The
benchmark refuses to run until regenerated golden calls pass and saves
failure receipts. This material supports the port; it does not guarantee 1.6×
under Linux. Existing Asahi code and original speed receipts remain unchanged.
